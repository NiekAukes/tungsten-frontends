# Phase 6: Validation mode

Status: not started
SPEC: §8.1 (wrap + fall-through rules), §8.2 steps 1–4, §8.6, §10

## Goal

With `validation.enabled`, every overworld chunk is generated by vanilla **and** computed by Tungsten, and the two are compared bitwise. This is built **before** the generation path, so that phase 7 can be checked against it, and so that it proves the buffers (final density, veins, ESH) are right before any block depends on them.

## Scope

1. **Mixin `NoiseChunkGeneratorPopulateMixin`**: `@WrapMethod` on `populateNoise` (SPEC §8.1). This phase implements:
   - no instance → `original.call`;
   - shape guard (height / min Y differ from the program's) → `original.call`;
   - validation on → `original.call`, then the comparison;
   - otherwise → `original.call` for now, with a `TODO(phase 7)`.
   The decision is a plain method `PopulateDispatch.decide(...)` with a unit test.
2. **Capture vanilla values**: in the `ChunkNoiseSampler` constructor, capture the wrapped final density (`cacheAllInCell(add(finalDensity, Beardifier))`) and the vein functions (SPEC §10; see `JAVA_TEST_PLAN.md` Step 5 in the old repo's history: `git -C <old tungsten repo> show 948f83a:JAVA_TEST_PLAN.md`). Confirm the local's `ordinal` against the 1.21.11 source. During `original.call`, record per-block values into a per-chunk buffer in Tungsten's layout. Keep the capture hooks no-ops unless validation is on.
3. **`tungsten.validation.Validator`**: bitwise compare (`doubleToRawLongBits`, NaN == NaN) per route: final density with beardify, vein toggle/ridged/gap, preliminary surface level (once per new ESH region, against `preliminarySurfaceLevel().sample(...)` on the 4-block grid). Per route: count, max abs error, max ULP, first bad world position.
4. **Logging**: one line per chunk with mismatches, totals every 256 chunks (§10).
5. **Dumps**: `<gameDir>/tungsten-validation/<route>/<cx>_<cz>/` with `meta.json`, `tungsten.bin`, `vanilla.bin`, `hostconsts.bin`, up to `dumpLimit` per route.
6. **Debug fault injection** (test aid): `-Dtungsten.dev.corruptRoute=<route>` flips one value in the Tungsten buffer, so the mismatch path and dumps can be demonstrated.

## Out of scope

Placing blocks from Tungsten densities (phase 7). Comparing block states.

## Acceptance

- [ ] `PopulateDispatchTest` covers each fall-through rule.
- [ ] Unit test for `Validator` on synthetic buffers: equal, one-off ULP, NaN vs NaN (equal), NaN vs number (mismatch); first bad position decodes correctly.
- [ ] **Vanilla run**: dedicated server, `validation.enabled=true`, fresh world, pregenerate a radius of ≥ 32 chunks around spawn plus one village and one ancient city area (use `/locate` + `/tp`, or Chunky if available in dev). **Zero mismatches** on all routes; totals line in the log.
- [ ] **Fault injection**: with `corruptRoute=final_density_with_beardify`, the log shows mismatches and `dumpLimit` dump folders appear with all four files; `meta.json` is valid JSON with the fields from §10.
- [ ] **JJThunder run**: same as vanilla, smaller radius. Zero mismatches, or every mismatch class written up in "Notes" with a dump and a reproducing harness command (then it's a compiler bug, not a phase failure — say so in the PR).

## Review checklist

- The capture mixin cannot change vanilla's results (it only reads).
- Validation off ⇒ no capture cost (check the guard).
- Dumps are bounded by `dumpLimit` under concurrency (atomic counter).
- Layouts and origins match phase 3's notes; index math has one helper, used by both sides.
