# Phase 5: Preparation on the dedicated server

Status: not started
SPEC: §3, §7.1 (dedicated part), §7.2–§7.5, §7.7, §9

## Goal

On a dedicated server, world load runs the full preparation: resolve the profile, pick the root, feed the datapacks, compile natively, check for code-registered worldgen, Janino, bind to the seed, write the record. The resulting `ProgramInstance` is registered for the overworld generator. **No chunk is generated by Tungsten yet** — that's phases 6–7.

The dedicated server comes first because it's synchronous and has no screens, so the pipeline can be tested without UI.

## Scope

1. **`tungsten.prepare.TungstenPreparation`**: one class, one method per stage, input = a small `PreparationInput` record (registries, enabled pack list, seed, overworld `DimensionOptions`, world dir), output = `PreparationResult`: `Active(ProgramInstance)` | `Inactive(reason)` | `Unsupported(reason, details)` | `Refused(message)`. A `StageListener` receives stage names (§7.2) and timings; the server logs them at INFO.
   - **Root** (§7.3): not a `NoiseChunkGenerator` → `Inactive`; `ChunkGeneratorSettings` entry without a key → `Unsupported("inline noise settings")`; else its id.
   - **Feed** (§7.4): `ResourcePackManager.getEnabledProfiles()` in order → `createResourcePack()` → each namespace → `findResources(SERVER_DATA, ns, "worldgen", …)` → `loadResource`. Close packs after.
   - **Code-registered check** (§7.5): `CodeRegisteredCheck.check(reachable, fedIds, registries) → List<problem>` as a separate, unit-testable class.
   - Janino + bind + instance (phase 3).
   - Record write (phase 4) on `Active`, and `EXACT` on `Inactive` (§7.3 proposal).
2. **`tungsten.prepare.TungstenRuntime`**: `Map<MinecraftServer, ProgramInstance>` (weak or cleared on `SERVER_STOPPED`) plus lookup by generator identity (§7.1 proposal). Logs pool peak at stop.
3. **Mixin `DedicatedServerLoadWorldMixin`**: `@Inject(HEAD)` on `MinecraftServer.loadWorld`, guarded by `instanceof MinecraftDedicatedServer`. Builds `PreparationInput`, runs preparation, applies `ServerDecision` (phase 4). On `Refused`/`Unsupported` it throws an exception that stops the server with the message (check how vanilla stops on `loadWorld` failure, so the log ends with our message and not a stack trace salad).
4. Wire `Availability`'s config check to `TungstenConfig.enabled` (removes the phase 2 TODO).

## Out of scope

`populateNoise`, client flow, validation.

## Acceptance

Each scenario is a `runServer` run with a fresh `run/world` (write a script `scripts/server-scenario.sh <name>` that sets up `server.properties`/datapacks and greps the log). Record results in the PR.

- [ ] **Vanilla default**: log shows the four stages with timings; `world/tungsten.json` has `EXACT` and the compiler version; `TungstenRuntime` has an instance (log line).
- [ ] **Amplified** (`level-type=minecraft:amplified`): root logged as `minecraft:amplified`.
- [ ] **Flat**: `Inactive`, server starts, record `EXACT`.
- [ ] **JJThunder datapack** in `world/datapacks`: compiles; reachable ids include JJThunder ids; stage timings recorded in "Notes".
- [ ] **Inline noise settings** (`generator-settings` with a custom JSON preset): server refuses to start and the message names `"profile": "OFF"` and `enabled: false`.
- [ ] **Record OFF**: server starts silently with no compile.
- [ ] **`enabled=false`**: no compile; record untouched.
- [ ] JUnit `CodeRegisteredCheckTest` covers: all fed; id only in registry; entry without key.
- [ ] Restart the server twice: one compile per start, no leftover instances (log shows instance count 1).

## Review checklist

- The mixin is a few lines; all logic is in `TungstenPreparation`.
- Packs are closed in `finally`.
- No compile happens on a client connected to a remote server (the mixin is guarded).
- Every user-visible message matches SPEC §9 wording.
